# Mirage wire protocol — v2

The contract between the Mac app (`Sources/Mirage`) and the Android app (`android/`).
Both sides implement both roles:

| Role | Who | Listens? | Mirage term |
|---|---|---|---|
| **Host** (has the screen, sends video, receives input) | Mac "Send my screen", Android "Send my screen" | connects out | initiator |
| **Client** (is the display, receives video, sends input) | Mac "Be a display", Android "Be a display" | listens + advertises | responder |

Byte-level golden values: [`vectors.json`](vectors.json) (generated by `Tools/make-vectors.swift`
from the real Swift code; both test suites must reproduce every value in it).

---

## 1. Transport

- **Video/control/input**: one TCP connection. `TCP_NODELAY` on, never cork (`TCP_NOPUSH` off).
  Android: `Socket.tcpNoDelay = true`, `trafficClass = 0x88` (AF41, video).
- **Audio**: a separate UDP flow (§7). Mac uses `serviceClass = .interactiveVoice`;
  Android uses `trafficClass = 0xB8` (EF, voice).
- **Discovery**: DNS-SD `_mirage._tcp`, advertised by the **client** (the display). TXT keys:

| key | example | meaning | since |
|---|---|---|---|
| `px` | `2304x1440` | panel pixels in current orientation | v1 |
| `pt` | `1152x720` | suggested points | v1 |
| `hz` | `60` | refresh | v1 |
| `lock` | `0`/`1` | pairing code required | v1 |
| `v` | `2` | protocol version | v1 |
| `os` | `macos`/`android` | client platform | v2 |
| `dpi` | `249` | physical pixels per inch (0 = unknown) | v2 |
| `audio` | `0`/`1` | client can play audio | v2 |

A missing `os` means `macos` (v1 peer).

---

## 2. Framing

Every message: 16-byte **little-endian** header + `payloadLength` bytes.

| off | size | field |
|---|---|---|
| 0 | 1 | type |
| 1 | 1 | flags |
| 2 | 2 | reserved, 0 |
| 4 | 4 | payloadLength (u32) |
| 8 | 8 | timestampMicros (u64, sender's monotonic clock, µs) |

Unknown message types must be **ignored**, not treated as an error. (v1 peers fail
`MessageHeader(decoding:)` on an unknown type, which is why a v2 peer only sends v2 types
to a peer that said `protocolVersion >= 2`.)

### Message types

| hex | name | dir | payload | v |
|---|---|---|---|---|
| 01 | hello | C→H | JSON `ClientHello` | 1 |
| 02 | helloAck | H→C | JSON `HostHelloAck` | 1 |
| 10 | videoParams | H→C | JSON `VideoParameterSets` | 1 |
| 11 | videoFrame | H→C | length-prefixed NAL units (4-byte BE lengths, "AVCC/HVCC"); flags bit0 = keyframe; timestamp = capture time | 1 |
| **12** | **reconfigure** | C→H | JSON `ClientHello` (full, updated) — rotation or scale change | 2 |
| 20 | input | C→H | 32-byte `InputEvent` | 1 |
| 30 | stats | C→H | JSON `ClientStats` | 1 |
| 31 | requestKeyframe | C→H | empty | 1 |
| 32 | frameAck | C→H | empty; timestamp echoes the frame's | 1 |
| 40 | ping | both | empty | 1 |
| 41 | pong | both | timestamp echoes the ping's. **v2: payload = 8-byte LE u64 responder clock (µs) at reply time** (v1 sends empty; readers accept both) | 1/2 |
| 50 | bye | both | empty | 1 |
| 60 | keyExchange | both | 64 bytes, cleartext (§6) | 1 |
| **70** | **audioConfig** | H→C | JSON `AudioConfig` — start/restart audio | 2 |
| **71** | **audioStop** | H→C | empty | 2 |

## 3. JSON payloads

Swift `JSONEncoder` defaults apply: **`Data` is a base64 string**, keys are the property
names, optionals that are nil are **omitted**. Decoders must ignore unknown keys and treat
missing v2 keys as their default.

### ClientHello
```json
{
  "protocolVersion": 2,
  "deviceName": "Galaxy Tab S9 FE",
  "pixelWidth": 2304, "pixelHeight": 1440,
  "pointWidth": 1152, "pointHeight": 720,
  "refreshHz": 60,
  "supportsHEVC": true, "supportsH264": true,
  "wantsInputForwarding": true,

  "platform": "android",          // v2, "macos" | "android"; absent = macos
  "physicalDPI": 249.0,           // v2, absent/0 = unknown
  "scalePreference": "crisp",     // v2, "crisp" | "larger" | "more" | "most"; absent = crisp
  "supportsAudio": true,          // v2, absent = false
  "audioUDPPort": 50123,          // v2, UDP port the client listens on for audio; absent = none
  "orientation": "landscape"      // v2, "landscape" | "portrait"; informative
}
```
`pixelWidth/Height` = the **physical panel in the current orientation** (Android: `Display.getMode()`
rotated to the current rotation, never the app window size). `pointWidth/Height` = the client's
suggestion; the host's geometry planner (§5) decides the final values.

A host accepts `protocolVersion` 1 and 2.

### HostHelloAck
v1 fields unchanged (`accepted, reason, hostName, codec, pixelWidth, pixelHeight, pointWidth,
pointHeight, fps, bitrateKbps, isHiDPI`). `pixelWidth/Height` here are the **stream** size.
v2 adds optional `"platform"` (host platform) and `"audioAvailable"` (bool).

### VideoParameterSets
```json
{"codec":"hevc","height":1440,"nalLengthSize":4,"parameterSets":["QAEM","QgE=","RAE="],"width":2304}
```
HEVC: `[VPS, SPS, PPS]`; H.264: `[SPS, PPS]`. Raw NAL units, **no** start codes, no length
prefix. Resent before every IDR.

### ClientStats
`{"framesDecoded":0,"framesDropped":0,"averageLatencyMs":0,"decodeMsAverage":0,"bytesReceived":0}`

### AudioConfig (v2)
```json
{
  "sampleRate": 48000,
  "channels": 2,
  "format": "s16le",
  "packetFrames": 240,            // 5 ms
  "playoutDelayMs": 60,           // playAt = hostTimeMicros + playoutDelayMs*1000 (host clock)
  "encrypted": false
}
```
Host sends it to the client's `audioUDPPort`, at the TCP peer's IP address.

## 4. InputEvent — 32 bytes, little-endian

| off | size | field |
|---|---|---|
| 0 | 1 | kind: 1 mouseMove, 2 mouseDown, 3 mouseUp, 4 scroll, 5 keyDown, 6 keyUp, 7 flagsChanged |
| 1 | 1 | button: 0 left, 1 right, 2 middle |
| 2 | 1 | clickCount (default 1) |
| 3 | 1 | isPreciseScroll (0/1) |
| 4 | 4 | x — f32, 0…1, **left→right** across the client's video view |
| 8 | 4 | y — f32, 0…1, **top→bottom** |
| 12 | 4 | deltaX f32 (mouseMove: relative px; scroll: see below) |
| 16 | 4 | deltaY f32 |
| 20 | 2 | keyCode u16 — **macOS virtual keycode** (kVK_*), always, whatever the platform |
| 22 | 2 | padding 0 |
| 24 | 4 | modifiers u32 — **CGEventFlags bits** |
| 28 | 4 | padding 0 |

Modifier bits: capsLock `0x10000`, shift `0x20000`, control `0x40000`, option `0x80000`,
command `0x100000`, numericPad `0x200000`, fn `0x800000`.

Scroll: `isPreciseScroll = 1` → deltas in pixels (trackpad/touch); `0` → lines (wheel).
Sign follows AppKit `scrollingDeltaY`: **positive = content moves down** (as with
"natural" scrolling: finger moves down).

Keycodes: the sender maps its native keycode to a macOS kVK code; a non-Mac host maps it
back. Android ↔ macOS table: `android/.../KeyMap.kt` (single source, used by both
receiver and host).

## 5. Display geometry (host decides)

`DisplayGeometry.plan(panelPx, physicalDPI, preference, platform)`:

| preference | virtual points | virtual pixels | stream pixels |
|---|---|---|---|
| crisp (default) | panel / 2 | panel | panel |
| larger | panel / 2 × 0.85 | 2 × points | panel |
| more | panel / 2 × 1.15 | 2 × points | panel |
| most | panel / 2 × 1.30 | 2 × points | panel |

Points rounded to even integers; pixels = 2 × points. Mac clients (`platform` = macos) always
get exactly what they asked for (v1 behaviour). When stream ≠ virtual pixels, the host captures
with scale-to-fit.

Galaxy Tab S9 FE (SM-X510): panel 2304×1440 landscape, 249 dpi → crisp = 1152×720 pt.

**Android host** (Mac is the display): virtual display = client's `pixelWidth×pixelHeight`,
`densityDpi = round(160 × pixelWidth / pointWidth)` (Mac 2× → 320).

## 6. Encryption (when a pairing code is set on both sides)

1. Each side sends `keyExchange`: `X25519 public key (32) ‖ HMAC-SHA256(codeSecret, publicKey) (32)`,
   `codeSecret = SHA256("mirage.pairing.v1:" + code)`.
2. Verify the peer HMAC (mismatch = wrong code, close). `shared = X25519(priv, peerPub)`.
3. `salt = min(pubA, pubB) ‖ max(...)` (lexicographic bytes).
   `key = HKDF-SHA256(ikm = shared, salt, info = "mirage.session.v1", L = 32)`.
4. Every message after that, **including ping/pong**, has
   `payload = AES-256-GCM(key, nonce, plaintext, aad = header)` → `ciphertext ‖ tag(16)`,
   where the AAD header is the real header with `payloadLength = plaintext + 16`.
5. Nonce (12 bytes): `[direction, 0, 0, 0, counter u64 LE]`. direction 0 = sent by the
   initiator (host), 1 = sent by the responder (client). One counter per direction, starting
   at 0, +1 per sealed message.

> **v2 fix**: v1's `PeerLink.deliver` answered ping/pong *before* decrypting, so their
> counter values were never consumed on the receive side, and encrypted links desynced at the
> first heartbeat. In v2 every non-keyExchange message is opened first, then dispatched.

Audio UDP (§7) reuses the session key with **direction byte 2** and `counter = seq`.

## 7. Audio over UDP (v2)

Packet: 16-byte LE header + payload.

| off | size | field |
|---|---|---|
| 0 | 1 | version = 1 |
| 1 | 1 | flags: bit0 encrypted |
| 2 | 2 | reserved 0 |
| 4 | 4 | seq u32 (+1 per packet; starts at 0 per TCP connection and **never restarts** within it, even across audioConfig — it is the audio nonce. Clients must not assume a new audioConfig starts at 0) |
| 8 | 8 | hostTimeMicros u64 — host monotonic capture time of the first sample |
| 16 | n | PCM s16le interleaved, `packetFrames × channels × 2` bytes (960 for 5 ms stereo) |

Encrypted: payload = AES-GCM(key, nonce `[2,0,0,0, seq as u64 LE]`, pcm, aad = 16-byte header).

**Playout**: every sample plays at `hostTimeMicros + playoutDelayMs×1000` on the host clock.
The client maps host time → its own clock using the clock offset from ping/pong (§8),
and corrects drift by resampling ±0.5 % at most (never by dropping samples, except to recover
from a gap of more than 100 ms). The host plays the same samples on its own speakers at the same
instant (Mac: `LocalPlayout`), so both outputs line up.

---

## 8. Clock sync

Each side already pings once a second. With v2 pongs:
`t0` = ping header timestamp (local), `t1` = pong payload (remote clock), `t2` = local receive time.
`rtt = t2 − t0`, `offset = t1 − (t0 + t2)/2` (remote − local). Keep the sample with the
lowest RTT in the last 10 s window; smooth with EWMA α = 0.1 on new minimum-RTT samples.
`remoteToLocal(t) = t − offset`.

Cross-device frame latency (stats overlay) = `localDisplayTime − remoteToLocal(captureTime)`.

## 9. Sequence

```
client                                   host
  │◄──────────── TCP connect ─────────────│
  │◄──────── keyExchange (if code) ──────►│
  │──── hello (ClientHello v2) ──────────►│  build virtual display / encoder
  │◄──── helloAck ────────────────────────│
  │◄──── videoParams, videoFrame(IDR) ────│
  │──── frameAck (per frame) ────────────►│  ≤3 unacked frames in flight
  │◄──── audioConfig ─────────────────────│  (if client.supportsAudio && host audio on)
  │◄═════ UDP audio packets ══════════════│
  │──── reconfigure (on rotation) ───────►│  rebuild display; new videoParams + IDR
  │──── input / stats / requestKeyframe ─►│
  │◄──────── bye ────────────────────────►│
```
